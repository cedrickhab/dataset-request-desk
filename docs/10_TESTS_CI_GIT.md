# Task 10: verification and delivery discipline
Add CI skeleton early in task01; expand as features land. PostgreSQL test database, pytest/pytest-django TransactionTestCase or transactional fixtures for real locks; frontend Vitest/Testing Library for state behaviors; minimal Playwright role workflow smoke when stable. Mock export randomness/clock. Do not use SQLite to claim PostgreSQL locking correctness.
Create scripts/check.sh fail-fast: Django check, migration drift check, Ruff, backend pytest on PostgreSQL, npm ci from lockfile, frontend lint/typecheck/tests/build. Command targets already-running isolated test environment or starts test services explicitly; avoid running migrations/tests against user DB. README one-command tests: docker compose -f compose.test.yaml run --rm check, with service dependencies and disposable DB. CI runs equivalent gate from clean checkout. Tasks incomplete must not be marked passed by skipping failing checks.
Git: check existing user files before staging; never git add unrelated secrets. Meaningful small commits after verified increments, not one giant final commit and not arbitrary hourly empty commits. Examples: Validate episode imports; Enforce delivery requirements; Show request status history; Retry failed export jobs. No claims of completed documentation when implementation is the change. No force push, history rewrite, automated merge or branch deletion. Branch build/dataset-request-desk, remote origin supplied by user. Repository creation remote is setup, not implicit login permission.
Install repo-local pre-push hook via core.hooksPath to invoke check script; runner itself runs checks too. Never --no-verify. If checks fail: fix, rerun, do not push. If checks pass: commit if meaningful change, push authorized branch, check CI for exact HEAD SHA using GitHub CLI/API if authenticated. CI AFTER push cannot cancel/remove that push; a failed CI blocks progression/merge and is fixed by another tested commit. Never claim CI green without observed result; missing remote/auth -> record block, continue independent local work, no fake push. Protection rules later can block merges until green. Avoid CI automatically pushing code or deploying.
Gate: meaningful auth/workflow/assignment/import tests, frontend behavior tests, clean startup test, negative cases and concurrency, observed same-commit CI success. Commit example: Verify workflows and add continuous integration.
