# Task 03: login, role enforcement and user management
Session login with Django password hashing and rotation of session key. GET /api/auth/csrf establishes CSRF token anonymously solely for login setup (document exception to brief). All other routes except login require active authenticated user; /health requires session. Docker uses internal DB readiness probe rather than public health.
React fetch uses credentials same-origin and X-CSRFToken on unsafe methods. Secure/HttpOnly session cookie, SameSite=Lax; Secure disabled only in explicit local HTTP config. CSRF checks apply to login too, not merely DRF authenticated endpoints. Anonymous me ->401, authenticated forbidden role ->403; inaccessible other-client request ->404. Invalidate deactivated user's sessions by active-user checks each request. Roles evaluated per request, not from stale UI cache.
No token/password logging. Login generic errors, basic throttling and documented shared-cache limitation. No OTP/2FA or email delivery. No hardcoded personal credentials. Secrets via ignored env; production must fail if secret absent/debug enabled (later).
Admin endpoints create user, list users paginated, patch role/active. Password validates with Django validators and hash setter. Lock admin-management transaction to guard last-admin race, audit actor/time and changes without passwords. Clients and operators forbidden. Prevent last-admin demotion/deactivation and self-deactivation. Avoid user deletion to preserve history.
Gate: tests login/logout, CSRF absent, wrong role, cross-client access, deactivation, role changes, last-admin guard. Commit example: Enforce login and role permissions.
